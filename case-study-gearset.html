Context

Using the product everyday meant I ran into small issues.

I wanted to improve the UI of the product... myself.

Gearset is a DevOps platform for Salesforce teams. I'm in the product constantly for customer calls, troubleshooting, and product demos. I run into the same UI issues our users do, and decided to fix them myself, since otherwise they may not get fixed at all.

I got access to the codebase and Claude Code, learned the UX team's workflows, and started fixing things.

The fixes

Four UI issues I found, fixed, and shipped.

Fix 01

Delegate access: a save button buried at the bottom of the list.

Admins managing org access had to scroll past every user to reach Save. Some customers have over 100 users on this page.

What I did, and why: I designed a paginated table in Figma and shared it with a UX colleague. He suggested reusing a new table component from elsewhere in the platform for consistency. I prototyped both in Claude, and chose the latter.

Impact: over 40% of visits to this page came from teams too large to see Save without scrolling. Two-thirds of those visits came from Enterprise accounts. For the largest teams, Save was buried 5+ seconds down.

After Scrollable table, save button always visible

126 users in a scrollable table. Save is always visible.

Fix 02

What's New search: results that required manual scanning to find the information.

Searching What's New returned matching results, but it didn't show where your term appeared. You had to manually read the results to find the relevant info.

What I did, and why: I used the design system to find the right highlight colour, and applied it to searched terms. Highlighting matches existing mental models, and lets users jump straight to the match. I toyed with ideas of making the product areas filter options, but the increased complexity meant I wanted to tackle it later.

Impact: X searches a month (tracking requested, data pending).

Before No highlighting of search terms

After Search terms highlighted in results

Fix 03

Error monitoring: a card that looked clickable but parts of it weren't.

The card looked like a single click target, but only part of it responded. Clicks on the rest did nothing.

What I did, and why: if something looks like one target, users treat it as one. I made the whole card clickable to match what that design pattern, and because a larger target is faster and easier to hit (Fitts's law).

Impact: every click on the card now does what the design promises, with no dead areas.

Before Clickable area smaller than the card

After Entire card responds to clicks

Fix 04

Agent window: resizing had no signal.

The agent window could be resized, but nothing signalled it. Users found it by accident or not at all, and one customer asked us to add the feature even though it already existed.

What I did, and why: a feature users can't discover might as well not exist. I used Claude Code to prototype some icons and hover states, and shared it with a UX colleague. She suggested looking for an existing component to reduce the lift. We found the component, shared it with Engineering, and got it implemented.

Impact: makes an existing feature discoverable for everyone using the Agent.

After Resize handle with hover state

The process

How a CSM ships code at Gearset.

Spot it.

I find friction from daily product use, log a ticket in Shortcut, and self-assign it.

1

Build it.

Depending on the extent of the change I either design in Figma first and validate it in Slack, or go straight into Claude Code. I create a feature branch, build it, and raise a PR.

2

Ship it.

I work through Engineering's code review, test in Staging, iterate, and ship to production.
